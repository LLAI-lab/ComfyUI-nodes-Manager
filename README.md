# ComfyUI-nodes-Manager

管理**插件往界面里塞的那些按钮**：自动探测装了哪些插件、界面上多了哪些按钮，
然后逐个调字号、图标大小、显示隐藏和位置。

装了几百个插件之后顶部按钮条会被撑爆（这台机器实测内容宽 2805px、视口 1920px，
溢出约 900px）。手写 CSS 能治，但选择器难写又容易失效 —— 这个插件把那件事做成了面板。

不改 ComfyUI 本体、不改任何别的插件、不写 `user.css`。配置单独存在用户目录。

## 装 / 用

放到 `ComfyUI/custom_nodes/ComfyUI-nodes-Manager`，重启 ComfyUI。
左侧竖栏会多一个滑块图标的「界面管理」页签。

面板里：

- **全局** —— 整条缩放、按钮间距、统一字号、统一图标字号、是否允许折行
- **按区域分组的条目列表** —— 每条可调：
  - 隐藏
  - 字号 / 图标大小 / 宽度 / 排序
  - 只留图标 / 只留文字（同时有图标和文字的条目才给这两个）
- 鼠标移到某一行，页面上对应的按钮会描橙色边，用来确认「改的是哪个」
- 改动**立即生效**（预览），点「保存」才落盘；「撤销改动」回到上次保存的状态

数值输入框留空 = 不干预，保持插件原样。

## 探测新插件

两路一起看：

- **磁盘侧**：扫 `custom_nodes` 目录，和上次记录比对，报出新装 / 消失的插件目录。
  首次运行只记基线不报新增（否则 500 个插件会一起冒出来说是新的）。
- **界面侧**：扫运行时 DOM，新出现的按钮标上「新」。
  第三方插件的按钮多是异步塞进来的，所以启动后会按 0.8s / 2s / 5s / 10s / 20s / 45s
  补扫几次，之后靠 MutationObserver 跟进。

`全局 → 新按钮默认显示` 关掉之后，以后新装插件加的按钮会默认隐藏，
需要时再到面板里放出来 —— 适合「界面已经调好了，不想被新插件打乱」的情况。

## 怎么认按钮的（为什么不用序号）

**不能按 `:nth-child(n)` 认。** 实测两次加载之间，插件按钮的先后顺序会变
（「构想台 / 资产库」「crystools / 应用管理器」的次序都漂）。

所以每个条目算一个**内容签名**：标签名 + 相对区域根的深度 + 专属 class + id +
aria-label/title + 内部图标类名 + 文字内容。几个要点：

- 文字里的数字会归一化成 `#`（`CPU 45%` → `CPU #%`）。监控条那类文字每秒都在变，
  照原样进签名的话 id 一直漂移，配置隔一秒就对不上。
- 标签名和深度必须进签名。`.actionbar-container > div.shrink-0` 里只有一个按钮时，
  外层 div 和里面的 button 文字、图标全一样，不加这两样会算出同一个 id，
  隐藏一个会把外层一起藏掉。
- 万一还是撞（同一排两个长得完全一样的按钮），按文档顺序补序号并标成「id 不稳定」，
  面板上有提示 —— 这种条目刷新后可能对不上。

样式不靠猜选择器：扫描时给元素打上 `data-nm-id="<签名>"`，CSS 一律写
`[data-nm-id="..."]`。属性值来自我们自己，不受前端版本和别的插件影响。
代价是 CSS 要等 JS 打标之后才生效，所以「隐藏」这一类额外生成一条 `:has()` 兜底规则，
在打标之前先把它藏住，压掉首屏闪动。

## 已实测环境

`comfyui-frontend-package 1.49.6` / ComfyUI `0.34.0`，1920 视口。
这个版本的界面结构有几点反直觉，写死选择器前值得知道（都是运行时实测的，
按源码推断会全部落空）：

- `#comfyui-body-top` 里**没有**顶栏，实测高仅 10px，只是旧版扩展的挂载点
- 真正的顶部 UI 在 `#graph-canvas-container` 内一层 absolute overlay 里
- 主菜单 / logo 不在顶栏，在左侧竖栏顶部
- 没有 File/Edit/Help 横向菜单栏，菜单全收进 logo 下拉
- 其余是 Tailwind 原子类 + Vue scoped 属性选择器，覆盖时都要 `!important`

区域定义集中在 `web/nm_zones.js` 的 `ZONES` 里 —— 前端升级后选择器要是失效了，
只用改那一处。面板会把「未出现在页面上」的区域标灰，一眼能看出哪条失效了。

## 几个坑（都是实测结论）

- **调宽常常没反应**：按钮宽度是内容（图标 + 文字）撑出来的，光写 `width` 会被顶回去。
  所以「宽度」这一栏同时会写 `min-width:0` 和 `overflow:hidden`。真想省横向空间，
  改字号或只留图标比硬调宽度有效得多。
- **整条缩放用 `zoom` 而不是 `transform: scale()`**：后者视觉变小但照样占原来的宽度。
- **折行光加 `flex-wrap` 无效**：按钮条宽度是 shrink-to-fit，可用宽度永远等于内容宽度，
  wrap 永不触发。所以「允许折行」会同时给它 `width:100%`，并用 `display:contents`
  把插件按钮外面那两层包装打平，让按钮直接参与 wrap（装箱最省）。
  副作用是包装层的 `gap` 会随之失效，需要自己在「按钮间距」里补。

## 文件

    __init__.py            入口：注册路由 + WEB_DIRECTORY，启动时打印探测结果
    engine/store.py        配置读写（清洗 + 原子写 + mtime 缓存）
    engine/scan.py         扫 custom_nodes，判定新增 / 消失
    engine/routes.py       HTTP 接口
    web/nodes_manager.js   前端入口：注入配置、注册侧栏页签、补扫
    web/nm_zones.js        区域定义 + DOM 扫描 + 内容签名（唯一写死选择器的地方）
    web/nm_style.js        配置 → CSS，打标与注入
    web/nm_panel.js        面板 UI
    selftest.py            后端自检，不需要 ComfyUI 在跑
    tests/fixture.html     前端自检夹具，在浏览器里跑

配置默认在 `ComfyUI/user/nodes_manager/ui.json`，
可用环境变量 `NODES_MANAGER_CONFIG_DIR` 改到别处。

## 接口

    GET  /nodes_manager/state    配置 + 磁盘插件清单 + 新插件
    POST /nodes_manager/config   写回 global / items
    POST /nodes_manager/seen     上报扫到的界面条目，返回其中哪些是新的
    POST /nodes_manager/forget   删掉若干条目的配置

和 ComfyUI 其它插件的接口一样没有额外鉴权 —— 能访问 ComfyUI 的人就能改界面配置。

## 自检

后端（配置清洗、存取回环、原子写无残留、插件扫描、新增/消失判定，
以及前端文件的导出符号和入口的 import 是否对得上）：

```
python selftest.py
```

跑在临时目录里，不碰真配置。

前端（DOM 扫描、签名稳定性、打标不串、CSS 真的生效）跑在浏览器里。
夹具 `tests/fixture.html` 按实测的真实结构搭了一份假顶栏 —— 包含两层包装里的按钮、
每秒变数字的监控条、毫无特征的裸 div。ES 模块要走 HTTP，不能用 `file://`：

```
python -m http.server 8792 --bind 127.0.0.1
# 然后浏览器打开 http://127.0.0.1:8792/tests/fixture.html
```

页面上会直接列出 32 条断言的 PASS/FAIL。
